# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

Static HTML/CSS/JS to start, with a planned eventual migration to Vite + TypeScript. Build accordingly so the migration stays low-friction (avoid patterns that would need a full rewrite).

## Users

The owner (Kaiden), building for themselves: a personal portfolio and reusable library of B2B SaaS site templates to draw from in future work, not a client-facing or third-party-facing product.

## Product Purpose

A growing library of B2B SaaS website templates covering the full product surface, not just marketing pages. Success means having a set of polished, reusable starting points that can be adapted quickly for future B2B SaaS projects.

## Positioning

A personal template library distinguished by covering the complete B2B SaaS surface area (marketing, product UI, auth, and content) rather than being another single-page landing template, and by holding each template to genuine craft rather than generic SaaS-template quality.

## Operating Context

Templates are built and iterated on individually, likely one at a time, each potentially with its own distinct visual identity. The library will grow over multiple sessions rather than being built in one pass.

## Capabilities and Constraints

- Planned template categories (open scope, to be built incrementally): marketing/landing pages, app shell / dashboard UI, auth & onboarding flows, and docs/changelog/blog surfaces.
- No fixed single brand system across the library — each template may carry its own visual world.
- Visual direction is not yet defined here by design (aesthetic choices are out of scope for product context). The user has Pinterest references and intends to provide a detailed prompt with specific constraints when starting each template's visual direction; that direction belongs in `new-work`/DESIGN.md for that specific surface, not in this file.

## Evidence on Hand

None yet. No existing copy, data, logos, or assets are on hand for any template. Future work must not fabricate testimonials, customer logos, pricing, or case studies — use realistic placeholder content clearly suited to a template/demo context.

## Product Principles

1. Cover the full B2B SaaS surface (marketing, product UI, auth, content) over time, not just landing pages.
2. Each template should reach genuine, distinct craft rather than repeating generic SaaS-template visual patterns.
3. Keep the static build honest to a future Vite + TypeScript migration — avoid throwaway structure.
4. Treat each template as its own visual world unless the user later asks for a shared system.
